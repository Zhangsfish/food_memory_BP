# Food Memory｜商业方案工作台

> 状态：商业假设与校园试验设计 v0.1；不是已验证的商业模式，也不是已完成的融资 BP。
> 版本日期：2026-09-25。

## 一句话

从个人吃饭记忆出发，组织有来源、可更新的真实体验，让 AI 根据提问者当下的需求，找到哪些人的哪些经历值得参考。

最值得验证的变化不是“再造餐厅评分”，而是：**在具体情境下，找到值得参考的人与经历，而不是只找到大众评分高的店。**

## 两个仓库，两个职责

- [`Zhangsfish/food_memory`](https://github.com/Zhangsfish/food_memory)：现有原始数据与格式。仍然是一顿饭一个记录，按作者和地区检索。
- 本仓库 `food_memory_BP`：商业方向、反证、用户研究、试验与未来 BP。这里的提案不自动改变数据仓库的规则。

本轮没有修改原始美食仓库，没有上线画像、KOL 排名、付费、分账、实名或 Web3 系统。

## 当前可核验的起点

2026-09-25 读取现有数据仓库：**1 位作者、2 条经历，均为北京**。已存在数据格式、作者/地区索引和贡献说明。不把文件数当用户增长，不把初始化通过当作完成外部用户测试。

原库 `CONTRIBUTING.md` 仍明确：广泛开放贡献前需要选定数据/内容许可。公开可见不等于已取得所有商业复用权。[证据与原库链接](research/EVIDENCE.md)

## 本轮的重要结论

**保留：**真实原话、可追溯作者、个人记忆与目的地检索、探索本人自述画像、从熟悉的校园小圈子验证需求。

**待验证：**作者画像是否改善选择；持续贡献是否自发；是否会出现被反复参考的人；局部数据密度能否改善推荐；是否有人付费。

**不能直接成立：**公开 GitHub 上“不发不给看”；按裸访问次数分账；用一个 KOL 总分表达所有口味；Web3 自动保证一人一号且诚实；“大厂不会做/有数据就追不上”。

工作建议是“公开原始数据路线与商业服务路线分别评估”，不是已经决定商业化。所有收费和画像上线仍待明确决策。

## 对外使用

本仓库目前公开。仅沉淀本轮明确讨论的项目内容；参与者私密资料、访谈个人信息、原始订单地址与身份材料不得放入这里。
